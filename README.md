## 開発の流れ

`main`ブランチへの直接のpushは禁止とします。

基本的に以下の流れで開発を行います。

1. `main`ブランチを最新の状態にする
2. `main`から作業用ブランチを作成する
3. 作業用ブランチで開発する
4. GitHubへpushする
5. Pull Requestを作成する
6. 他のメンバーにレビューしてもらう
7. 問題がなければ`main`へmergeする

```text
main
  ↓
作業ブランチを作成
  ↓
開発
  ↓
push
  ↓
Pull Request
  ↓
レビュー
  ↓
mainへmerge
```

## ブランチルール

作業内容に応じて、以下の形式でブランチを作成します。

### 新機能・機能追加

```text
feature/機能名
```

例：

```text
feature/home
feature/seat-map
feature/reservation
```

### バグ・不具合修正

```text
fix/修正内容
```

例：

```text
fix/mobile-seat-map
```

## 環境変数

APIキーやパスワードなどの秘密情報は、GitHubへpushしないでください。

環境変数を使用する場合は`.env`を使用し、`.gitignore`の対象にします。

必要な環境変数については`.env.example`で共有します。

## 注意事項

* `main`ブランチへ直接pushしない
* 作業を始める前に`main`を最新の状態にする
* 作業ごとにブランチを作成する
* Pull Requestを通して`main`へmergeする
* `.env`など秘密情報を含むファイルをGitHubへpushしない
* 分からないことや大きな変更を行う場合は、メンバー間で相談してから進める
